# Skills index

Route here first, then open the single `<name>/SKILL.md` that matches the work
in hand. Do not survey this directory or read several skills to find out which
one applies — each is thousands of words, and the wrong one costs more context
than it saves.

| Skill | Open it when you need to |
|---|---|
| `design` | Turn a specification or goal into a planned, tested pipeline. |
| `blocks-reference` | Compare available blocks and choose tools by modality, cost, strength, and limitation. |
| `scripting` | Write, run, or test a standalone pipeline script (CLI flags, cycling, build process). |
| `debugging-inputs` | Fix input preparation: chain IDs, ligands, parsing, malformed structures. |
| `build-block` | Add a new block for a tool the harness does not yet wrap. |
| `slurm-background` | Submit detached Slurm work for pilots, production, or campaigns. |
| `slurm-interactive` | Hold a persistent interactive Slurm session for live iteration. |
| `auto-research` | Iteratively improve a pipeline using user thresholds or an existing Chaperone scorer. |
| `setup` | Install or verify Chaperone itself. Rarely needed — the container is prebuilt. |
| `visualize` | Inspect structures in PyMOL. |
| `notebook-editing` | Edit, create, or execute Jupyter notebooks. |
| `rosetta-params` | Generate or debug Rosetta `.params` files for a ligand. |
| `order-collection` | Prepare wet-lab orders. Not part of a computational submission. |
